# 基础构造与内存释放

本笔记分析 Fini 的基础能力及其对内存释放的影响。语言行为见 [语言参考](../spec/README.md)；这里的内存推论尚无动态数据实现或安全证明。

## 1. 研究起点

SICP §1.1 用三种机制组织语言：基本元素、组合手段、抽象手段，并同时关注数据与计算过程。参考 [SICP 第二版，MIT 提供的原文 PDF，§1.1](https://web.mit.edu/6.001/6.037/sicp.pdf)。本项目借用这个分析框架，不继承书中使用的 Scheme 语言模型。

下面关于本语言的能力选择及内存影响，都是本项目的推导，不是 SICP 给出的无 GC 方案。

第一阶段研究输入值如何通过表达式转换为结果值，用来分析组合和函数抽象。这个最小模型无需立即支持通用计算或任意重复计算。

## 2. Primitive elements：基本元素

应先回答“语言操作什么”和“最小计算是什么”，再决定关键字。

| 能力 | 为什么研究它 | 最小方案 | 替代与代价 |
| --- | --- | --- | --- |
| 表达一个值 | 组合必须有起点 | 整数字面量 | 只有一个常量更小，但难以展示有意义的计算；文本等数据会增加存储问题 |
| 表达判断结果 | 让选择条件含义明确 | 独立布尔值 | 用整数兼任真假可减少值种类，却要增加真假转换规则 |
| 原始计算 | 从值产生新值 | 整数加、减、乘及比较 | 更少运算足够做部分演示；除法会引入舍入、除零等新问题，暂缓 |
| 名称求值 | 使用已命名的结果 | 名称取出绑定的值 | 名称属于引用表达形式，不是额外的可操作地址值 |

v0 不包含空值、浮点数、字符串、数组、地址或自定义数据类型。这些能力需要各自定义可观察行为，并以具体计算任务说明必要性。

v0 使用单一有符号 64 位整数，运算越界时终止计算并报错。表示大小固定，不必为了数值增长而动态分配；任意精度整数则可能引入随数值增长的存储。

## 3. Means of combination：组合手段

最基本的组合是让一个表达式的结果成为另一个计算的输入，例如 `((2 + 3) * 4)`。组合后的形式仍能作为一个表达式使用，避免每种组合都引入另一套语句规则。

基础组合包括：

- 运算嵌套与函数调用：建立由小计算形成大计算的方式。
- 条件表达式：先判断，再只求值选中的分支；两个分支都产生同类结果。
- 局部变量定义：命名一个已求值的结果，在块内后续表达式中复用。

必须一起明确：操作数求值顺序、参数是否先求值、条件是否只执行一个分支、非法分支是否仍接受静态检查。只列语法不能构成语义。

“组合计算”与“组合数据”是不同的研究问题。函数和嵌套运算足以演示前者；复合数据需要进一步回答构造、取出、相等、更新和大小。第一轮先不放入复合数据，但之后必须用它验证无 GC 方向，不能永久用标量例子代替该验证。

## 4. Means of abstraction：抽象手段

抽象的最低要求是把一段计算命名，使调用者只需知道输入和结果。

| 抽象层次 | 候选能力 | 获得什么 | 新增问题 |
| --- | --- | --- | --- |
| 给结果命名 | 局部变量 | 不重复书写或计算一个子表达式 | 名称作用域、遮蔽和绑定时机 |
| 给计算命名 | 有参数的具名函数 | 同一规则作用于不同输入 | 参数求值、函数作用域、返回结果 |
| 给数据组合命名 | 暂缓复合数据抽象 | 将来可隐藏数据表示 | 数据共享、访问与存储释放 |

具名函数不必同时成为可传递、可保存的值；函数也不必立即捕获外层局部环境。明确输入和结果的函数足以支撑第一阶段；更强的函数抽象需要单独分析表达能力和存储成本。

递归能表达重复计算，是重要能力，但它不是“函数可命名”的必然组成部分。v0 使用无递归的有限组合，后续再比较循环与递归带来的能力和分析成本。

## 5. 编译期内存释放

### 5.1 必须分开三个层面

1. **语义值**：例如整数 9，按语言规则参与计算。
2. **实际存储**：实现可能把值放在寄存器、栈或动态分配的空间，也可能复制或共享表示。
3. **释放安排**：编译器确定哪些执行路径上不再需要某份存储，生成释放操作；操作通常在程序运行到相应位置时执行。

Fini 的“编译期内存释放”指第三点，不表示运行时不分配，也不表示编译器必须预知每次分配的大小和释放的墙上时刻。不承诺最早释放；具体动态释放算法仍未选择。

词法作用域结束、函数返回、某个名称最后一次出现，都不能单独证明一份实际存储可以释放。编译器需要考虑所有后续使用，包括其他名称、调用中的参数和返回结果。

### 5.2 从基础语义逐项推导

| 候选设计 | 对释放分析的帮助 | 仍需处理的边界 |
| --- | --- | --- |
| 不可变的值与绑定 | 后续读取含义稳定，不必追踪值被覆盖后带来的变化 | 多个名称仍可能使用同一个值，实际存储共享不能被忽略 |
| 表达式结果明确 | 子表达式的输入、输出容易描述 | 中间结果可能被外层保存或返回 |
| 确定的严格求值 | 哪些参数先产生、何时交给函数较清晰 | 没被函数使用的参数也可能产生存储和计算成本 |
| 条件只执行选中分支 | 可沿每条分支分别安排释放 | 分支汇合处的结果仍然有效，未执行路径不能承担清理 |
| 词法作用域 | 可确定名称的含义，简化使用关系 | 存储的有效范围可能跨越该名称的作用域 |
| 具名函数、无环境捕获 | 调用目标和输入较明确 | 被调用者不能释放调用者仍需使用的输入；返回结果可能沿用输入表示 |
| 调用关系无环 | 每个函数的结果与输入关系可以按依赖顺序分析 | 表达能力受限，分析规模和内存开销仍需验证 |
| 暂无复合数据和修改 | 暂不产生可修改的对象图 | 不能证明未来集合、共享结构或环状数据同样可处理 |

这些帮助只是研究推论，还没有实现或证明。不可变也不自动保证没有环；若未来允许特殊构造或函数环境互相引用，仍需重新分析。

### 5.3 存储共享与释放的反例

以下示例遵循 [v0 语义](../spec/v0.md)，小整数及中间结果均在范围内。标量可以直接存储；例子说明未来共享表示的分析要求，不表示当前必须动态分配。

**名称复用不等于存储复制。**

```text
fn main() -> Int {
  let x = (2 * 3)
  let y = x
  (x + y)
}
```

结果是 12。当前整数可以直接复制；若后续数据的 `x`、`y` 使用同一份动态存储，则不能因一个名称读完，就忽略另一个名称的后续读取而释放存储。两种表示都必须保持相同语义；使用者不必多写内存操作。

**返回结果可能继续使用输入的表示。**

```text
fn same(n: Int) -> Int { n }
fn twice_square(n: Int) -> Int {
  let result = same((n * n))
  (result + result)
}
fn main() -> Int {
  twice_square(3)
}
```

结果为 18。`same` 返回时，返回值仍被调用者需要。即使 `same` 的局部名称消失，也不能无条件销毁结果使用的存储；也不能无条件销毁实参。函数边界需要描述哪些存储仍被外层计算需要。

**分支产生的结果活到汇合点之后。**

```text
fn magnitude(n: Int) -> Int {
  let result = if (n < 0) {
    -n
  } else {
    n
  }
  (result * result)
}
fn main() -> Int {
  magnitude(-3)
}
```

结果为 9。某一路径的新结果与另一路径沿用的输入都要支持后面的乘法。释放安排必须随实际路径正确执行，不能只按源码行号划一个固定结束点。

### 5.4 成功标准与尚未证明的部分

后续内存研究至少需要满足：

- 任何仍可能被后续计算读取的存储都有效。
- 每份动态分配的存储只被正确释放一次；共享表示也遵守这一点。
- 正常完成的计算中，不再被需要的动态存储最终得到释放；结果仍有效，直到结果使用结束。
- 分支、跨函数传参及返回都符合上述条件，无需运行时扫描对象图来判断存活。

最早释放与低峰值内存是额外的效率目标。把临时存储全部留到整个程序结束，可能安全且没有 GC，却不能充分验证“编译器自动安排有用的释放”。应在后续实验中明确释放粒度，测量峰值与释放位置。

仅支持固定范围标量的原型可以验证求值规则，但几乎无法验证动态存储回收。有界整数不会自动提供大小随数值增长的存储例子；下一轮复合数据研究至少需要一个大小可随输入变化的值，以及复用、返回、条件分支的实验。数据种类先讨论再加入。

暂不承诺：任意程序的最早释放、递归和任意数据图的完整分析、内存耗尽时的语言行为、运行时完全没有辅助元数据、内存使用必然有常数上界。无 GC 不自动意味着这些承诺成立。

## 6. 研究顺序

先用最小程序与反例验证语义原型，[语法问题](../questions/01-language-design.md) 随实验逐项处理。动态数据阶段选择一种最小数据形式，研究名称复用、函数返回和分支结果的释放安排；证据不足时调整模型，不直接引入复杂内存机制。
