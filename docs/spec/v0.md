# 语义

本文描述 Fini v0 的类型、求值、作用域和错误规则。源码形式见 [语法](syntax-v0.md)，计划采用的原型路线见 [项目说明](../../README.md#实现)。

## 程序结构

程序由顶层具名函数定义组成，必须包含唯一的入口函数 `main`。`main` 不接受参数，结果类型为 `Int` 或 `Bool`；其正常返回值是程序结果。程序开始时调用 `main`，其他函数定义本身不执行函数体。顶层不允许变量定义或独立计算表达式。

表达式支持字面量、名称读取、一元取负、二元运算、条件选择和直接函数调用。函数体及条件分支是代码块：可以先按行定义局部名称，最后一个表达式产生块的结果。

以下清单概括表达式结构，不是完整解析器规格。词法与排版的剩余问题见 [设计问题](../questions/01-language-design.md)。

```text
类型       T ::= Int | Bool
表达式     e ::= 整数字面量 | true | false | 名称
              | -e
              | (e op e)
              | if e 块 else 块
              | 函数名(e, ...)
运算符    op ::= + | - | * | == | <
局部定义       ::= let 名称 = e
块             ::= { 零个或多个局部定义，最后一个 e }
函数定义   d ::= fn 函数名(参数名: T, ...) -> T 块
```

暂不支持赋值、循环、递归、复合数据、函数值、局部函数和环境捕获；也不加入除法、浮点数、隐式转换与运算重载。

## 程序结果

原型运行接口在 `main` 正常返回后向标准输出打印一次结果：`Int` 使用十进制，`Bool` 使用 `true` 或 `false`，随后换行。结果不作为进程退出码。

计算发生错误时不打印正常结果；诊断格式与退出状态仍属于运行接口的设计问题。自动打印由生成程序的入口包装完成，不提供语言内置打印函数。

## 类型与运算

- `Int` 是唯一整数类型，范围为 −9223372036854775808 至 9223372036854775807，即 −2^63 至 2^63−1。范围不随机器变化。
- 整数字面量可以表示负数；字面量本身超出范围是编译错误。最小负整数可以直接作为字面量使用，不要求先构造一个超范围正整数再取负。
- `Bool` 只有 `true` 与 `false`，与整数之间没有自动转换。
- 值按内容理解，不提供观察实际存储身份的操作。
- `+`、`-`、`*` 接受两个 `Int`，计算精确的数学结果；结果在范围内则返回该整数，超范围则产生运行时错误并终止当前计算，不回绕、不截断。
- 一元 `-` 接受 `Int`，先计算操作数，再取相反数；最小整数的相反数越界，产生相同的运行时错误。直接写出的负整数字面量按带符号范围检查。
- `<` 接受两个 `Int`，返回 `Bool`。`==` 接受两个相同类型的值，按数值或真假比较，返回 `Bool`；不同类型比较是编译错误。
- 二元运算先求值左侧，再求值右侧，最后运算。某一步出错，后续步骤不执行。

越界运算统一按运行时规则处理，不要求编译器先计算常量表达式。未来优化可以提前计算，但必须保留原程序的结果、错误和分支行为；不能因此拒绝原本合法的未执行分支。

## 名称与作用域

局部定义按代码块中的顺序执行。先在当前可见环境中求值初始化表达式一次，再建立新名称；新名称在自己的初始化中不可见，从定义之后到当前块结束可见。

函数体和条件分支形成局部作用域；内层可以读取外层名称，块内定义不进入块外。代码块的最后一个表达式产生结果，块中不添加独立赋值、任意表达式语句或提前返回。

- 同一作用域不得重复定义同名变量。
- 内层不得定义仍可见的外层同名变量，包括函数参数。
- 两个互不包含的函数，或两个互不包含的分支中的局部作用域，可以各自使用相同名称。
- 参数和局部名称定义后不能重新赋值，可以重复读取，不限制读取次数。

同一个块连续两次定义 `x` 是编译错误；参数为 `x` 的函数中定义局部 `x`，也因名称冲突而拒绝。具体按行写法见语法文档。

## 函数与调用

顶层函数名唯一，同一个参数表中的名称唯一。所有函数定义对直接调用可见，定义顺序不影响含义。

值名称用于读取值，函数名用于直接调用，局部值不能改变调用目标。函数不能作为普通值保存、传递或返回。函数体只能读取参数与自身局部名称，不能读取调用者的局部名称。

参数和结果必须标注 `Int` 或 `Bool`；局部名称的类型由初始化表达式确定。实参数量、类型和函数体结果必须符合声明。

调用先从左到右求值所有实参，每个实参求值一次，再建立参数绑定并求值函数体。未使用的参数也先求值；任何实参出错，函数体不执行。

静态调用关系不得有环，未执行分支中的调用也计入检查；直接递归、相互递归都拒绝。

## 条件

`if` 的条件必须为 `Bool`。先求值条件，再只求值选中分支；两个分支必须有相同类型。未选中的分支不执行，但仍接受名称和类型检查。

## 错误

整个程序，包括未调用函数和未选中分支，在执行前接受检查。语法、名称、字面量范围、类型、参数数量、定义冲突和递归错误在编译时拒绝。

运算越界在实际执行该运算时发生，终止当前计算并报告错误；本版没有捕获、恢复或把错误当值传递的能力。外部如何显示诊断留到运行接口设计。

正常组合：

```text
fn square(x: Int) -> Int { (x * x) }
fn main() -> Int {
    let n = (2 + 3)
    square(n)
}
```

得到 25，`n` 的初始化计算一次。

分支内的越界运算不会在未执行时触发：

```text
if true { 1 } else { (9223372036854775807 + 1) }
```

得到 1；反之，直接执行 `(9223372036854775807 + 1)` 产生运行时越界错误。字面量 `9223372036854775808` 本身则是编译错误，即使它位于未执行分支。

最小负整数有效，但其相反数超出范围：

```text
fn negate(n: Int) -> Int { -n }
fn main() -> Int {
    negate(-9223372036854775808)
}
```

执行时取负越界。直接使用最小负整数字面量仍然合法；完整词法细节见语法文档。

未使用的实参仍执行：

```text
fn first(a: Int, b: Int) -> Int { a }
fn main() -> Int {
    first(1, (9223372036854775807 + 1))
}
```

第二个实参越界，整个计算出错，不返回 1。

下列形式是编译错误：

| 示例 | 原因 |
| --- | --- |
| `(true + 1)`、`(1 == true)`、`-true` | 参数类型不符合运算规则 |
| `if 1 { 2 } else { 3 }` | 整数不能直接充当条件 |
| `if true { 1 } else { false }` | 分支类型不同 |
| `if true { 1 } else { missing }` | 未执行分支也有未绑定名称 |
| 定义 `x` 的初始化读取 `x`（没有外层 `x`） | 初始化读取尚不存在的名称 |
| 重复局部名称、局部名称与仍可见的参数同名 | 定义冲突 |
| `square(true)`、`square(2, 3)`（使用上面的声明） | 实参类型或数量错误 |
| `fn bad(x: Int) -> Bool { x }` | 函数结果类型错误 |
| 直接或相互递归 | 调用关系有环 |
| 缺少 `main`，或 `main` 声明了参数 | 入口函数不符合程序结构 |
| 顶层变量定义或独立计算表达式 | 顶层只允许函数定义 |

## 内存

这些值的表示大小固定，v0 无需为了表示数值或保存函数环境而动态分配。这只减少当前模型的问题，不证明后续动态数据的释放已经解决。

项目目标采用“编译器静态安排释放操作，运行时执行”的解释，不要求最早可能的释放或最低峰值内存；仍需避免长期保留无用动态存储，不以进程退出作为充分的回收成果。

v0 不定义动态释放算法，也不提供手动内存管理操作。复合数据研究需要覆盖动态大小、名称复用、函数返回和分支汇合，再验证存储安全与释放位置。资源耗尽与外部结果消费接口留到相应实现阶段。

[Go 原型](README.md#原型实现) 生成 Go 源码，构建产物依赖 Go 运行时，用来验证语言行为。最终无 GC 的动态释放方案需要独立实现与验证。
